## 1. Intuition

In machine learning benchmarks, accuracy scores above 99% often look impressive, but in the context of sensor-based crop monitoring, they can be deeply misleading. In this project, the headline sensor model achieves **0.994 test accuracy** on the single held-out split and **0.986 macro-F1** with a decision tree. Does this mean our model detects real-world crop nutrition stress with 99.4% biological accuracy?

**The short answer is NO.**

The reason lies in how the ground-truth labels were generated. In living agricultural systems, verifying whether a plant suffers from true nutrient deficiency requires leaf tissue destructive testing, sap analysis, or an experienced agronomist. In our sensor datasets (Lettuce, Spinach, Tomato), the target labels were generated by a **deterministic Python script** applying hard action bands:
- If solution pH is below 5.5, label as `pH_Low`.
- If solution EC is above 2.5, label as `EC_High`.
- If all parameters sit inside their target bands, label as `Normal`.

A Decision Tree is an algorithm that searches for orthogonal, axis-aligned splits on individual features ($x_i \le \theta$). When trained on rule-derived data, the decision tree is not discovering hidden biological patterns; it is simply **reverse-engineering the exact if-else rules** written into the labeling script. High accuracy only proves that the model is a faithful compiler of the developer's rulebook.

## 2. Mathematical Formulation & Formal Definition

Let $\mathbf{x} = [x_1, x_2, \dots, x_d]^\top \in \mathbb{R}^d$ represent a vector of physical sensor readings (e.g. pH, EC, water temperature, humidity).

In rule-derived datasets, the target label $y \in \{1, \dots, K\}$ is determined by a deterministic mapping function $f_{\text{rules}}: \mathbb{R}^d \to \{1, \dots, K\}$ defined by axis-aligned half-spaces:

$$
f_{\text{rules}}(\mathbf{x}) = \sum_{k=1}^K k \cdot \mathbb{I}\left( \mathbf{x} \in \mathcal{R}_k \right)
$$

where each decision region $\mathcal{R}_k$ is a hyper-rectangle formed by intervals $[\theta_{j, \text{low}}, \theta_{j, \text{high}}]$:

$$
\mathcal{R}_k = \left\{ \mathbf{x} \in \mathbb{R}^d \;\middle|\; \forall j \in \{1, \dots, d\}, \; \theta_{j, \text{low}}^{(k)} \le x_j \le \theta_{j, \text{high}}^{(k)} \right\}
$$

A Decision Tree partition function $T(\mathbf{x})$ partitions the input space into disjoint axis-aligned hyper-rectangles $R_m$:

$$
T(\mathbf{x}) = \sum_{m=1}^M c_m \mathbb{I}(\mathbf{x} \in R_m)
$$

Because the true labeling function $f_{\text{rules}}$ is already composed of axis-aligned hyper-rectangles, the decision boundary error approaches zero:

$$
\lim_{\text{depth} \to D} \mathbb{P}\left( T(\mathbf{x}) \ne f_{\text{rules}}(\mathbf{x}) \right) = 0
$$

Thus, empirical risk minimization on rule-derived labels produces zero approximation error, regardless of whether the physical action bands reflect true biological plant health.

## 3. From-Scratch Implementation (NumPy / Pure Python)

The following self-contained script generates synthetic hydroponic sensor data using threshold rules and shows that a basic 1D threshold split recovers the exact underlying rule boundary:

```python
import numpy as np


def assign_ph_label(ph_values: np.ndarray) -> np.ndarray:
    """Ground truth labeling script: rule-derived threshold."""
    # Action band: pH must be >= 5.5, otherwise pH_Low
    return np.where(ph_values < 5.5, "pH_Low", "Normal")


def find_best_split_from_scratch(X: np.ndarray, y: np.ndarray) -> float:
    """Find the single threshold that maximizes Gini information gain."""
    classes = np.unique(y)
    best_gain = -1.0
    best_threshold = None

    def gini(labels):
        if len(labels) == 0:
            return 0.0
        _, counts = np.unique(labels, return_counts=True)
        probs = counts / len(labels)
        return 1.0 - np.sum(probs**2)

    parent_gini = gini(y)
    sorted_x = np.sort(np.unique(X))
    candidates = (sorted_x[:-1] + sorted_x[1:]) / 2.0

    for thresh in candidates:
        left_mask = X <= thresh
        right_mask = ~left_mask

        left_y = y[left_mask]
        right_y = y[right_mask]

        n = len(y)
        gain = parent_gini - (len(left_y) / n * gini(left_y) + len(right_y) / n * gini(right_y))

        if gain > best_gain:
            best_gain = gain
            best_threshold = thresh

    return float(best_threshold)


if __name__ == "__main__":
    # Generate continuous random pH readings between 4.0 and 8.0
    rng = np.random.RandomState(42)
    ph_readings = rng.uniform(4.0, 8.0, size=500)
    labels = assign_ph_label(ph_readings)

    learned_split = find_best_split_from_scratch(ph_readings, labels)
    print(f"Documented rule threshold: 5.500")
    print(f"Learned decision split:   {learned_split:.4f}")
    assert abs(learned_split - 5.5) < 0.05, "Failed to recover rule threshold!"
    print("Verification passed: Tree split directly recovered the labeling rule.")
```

## 4. Production & Library Usage

In production, scikit-learn's `DecisionTreeClassifier` automatically constructs tree branches. We can inspect the internal tree attributes `tree_.feature` and `tree_.threshold` to extract all learned decision boundaries:

```python
from sklearn.tree import DecisionTreeClassifier
import pandas as pd

df = pd.read_csv("processed_data/sensor/lettuce/train.csv")
features = ["ph", "ec", "water_temp", "humidity", "air_temp"]
X, y = df[features], df["label"]

dt = DecisionTreeClassifier(criterion="entropy", max_depth=5, random_state=42)
dt.fit(X, y)

# Inspect internal split thresholds
tree = dt.tree_
for i in range(tree.node_count):
    if tree.feature[i] >= 0:
        feat = features[tree.feature[i]]
        thresh = tree.threshold[i]
        print(f"Node {i}: {feat} <= {thresh:.4f}")
```

**Key Discovered Splits on Lettuce:**
- `ph <= 5.45` (recovers documented lower band `5.50`)
- `ph <= 7.05` (recovers documented upper band `7.00`)
- `ec <= 2.505` (recovers documented upper band `2.50`)
- `water_temp <= 26.05` (recovers documented upper band `26.00`)

## 5. Failure Modes, Edge Cases & Debugging

When evaluating models trained on rule-derived targets, three critical failure modes occur:

1. **Failure Mode 1: False Sense of Security (Metric Mirage)**
   - *Symptom:* The data science report claims "99.4% diagnostic accuracy" based on held-out test splits.
   - *Reality:* The model will fail completely in field conditions if physical sensors drift or if environmental conditions violate the unmodeled assumptions.
   - *Mitigation:* Require grouped cross-validation across calendar dates (yielding a realistic ~0.70 macro-F1) and explicitly disclaim field accuracy in all customer-facing reports.

2. **Failure Mode 2: Sensor Miscalibration Blindness**
   - *Symptom:* An aged pH probe reads 5.2 when the true solution pH is 6.0.
   - *Outcome:* The tree outputs `pH_Low` with 100% confidence. The model cannot detect that the plant is healthy and the hardware is drifting.
   - *Mitigation:* Pair sensor inference with visual leaf inspection (computer vision) to cross-check diagnosis before dosing acid/base.

3. **Failure Mode 3: Biological Adaptation Disconnect**
   - *Symptom:* High-yield cultivars or seasonal heat-tolerant varieties can thrive at 27°C water temperature.
   - *Outcome:* The model rigidly alarms `WaterTemp_High` because static if-else boundaries do not account for cultivar plasticity or microclimate buffering.

## 7. Self-Check Questions (Teach-Back Review for Sushil & Yashwant)

1. **Q1:** If our Random Forest achieves 0.994 accuracy on the lettuce test split, why is it forbidden to tell our professors or growers that it has 99.4% accuracy?
   - *Answer:* Because the labels were created by an if-else rule script on the same sensor numbers, not by an agronomist diagnosing real plants. 99.4% accuracy only measures how closely the tree reproduced the developer's script.

2. **Q2:** Why are Decision Trees and Random Forests so much better at fitting these datasets than Logistic Regression or SVM?
   - *Answer:* Because the rule-derived classes are defined by axis-aligned bounding boxes (step functions on individual variables). Decision trees partition feature space using orthogonal cuts, matching the exact mathematical geometry of the rules. Linear models and smooth kernels struggle with sharp rectangular corners.

3. **Q3:** What is the difference between our headline grouped 5-fold CV score (~0.70) and the single test split score (0.986)?
   - *Answer:* The single test split is "one favourable split" where observations from similar calendar days shared predictable values. The grouped 5-fold CV tests generalization across completely disjoint calendar days, accounting for day-to-day experimental variance.

4. **Q4:** What role does the Image Model play in mitigating this limitation in our final architecture?
   - *Answer:* The image model is trained on photographic leaf symptoms from living plants. By combining sensor alarms with image validation, the system avoids dosing chemicals when only the sensor probe has drifted.
